# Common documentation paths used in release preparation. The packer treats
# overlap on these as SHARED_INFRA rather than a collision, so declaring them
# honestly in a Track's `_touches:` no longer serializes the whole plan.
#
# pyproject.toml and VERSION are deliberately NOT here: pyproject is mind-meld's
# version source of truth and VERSION mirrors it. Two Tracks that both claim
# the same version merge cleanly in git, but only one tag can exist for that
# version: the first merge creates it, and the second merge is not included
# in that version's tag. release.yml will not force-advance `latest` to an
# untagged commit (the latest-advance step compares `git rev-parse "$tag^{commit}"` against
# HEAD and skips with a warning), so a dev-dep-only pyproject.toml edit is
# safe. Keep final version allocation, bump reconciliation and release-bearing
# merges coordinated and serialized; implementation may proceed in parallel
# Conductor workspaces. Keep both files out of this set so the packer still
# detects competing version edits. See ROADMAP.md's release admission gate;
# parallel-workspace version collisions remain a known deferred gap.
