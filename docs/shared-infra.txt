# Paths every release-bearing Track touches. The packer treats an overlap on
# these as SHARED_INFRA rather than a collision, so declaring them honestly in
# a Track's `_touches:` no longer serializes the whole plan.
#
# pyproject.toml is deliberately NOT here, even though mind-meld has no VERSION
# file and pyproject is its version source of truth. Two Tracks that both claim
# the same version merge cleanly in git, but only one tag can exist for that
# version: the first merge creates it, and the second's code never gets tagged
# at all. release.yml will not force-advance `latest` to an untagged commit
# (the latest-advance step compares `git rev-parse "$tag^{commit}"` against
# HEAD and skips with a warning), so a dev-dep-only pyproject.toml edit is
# safe. Serialization of version-claiming Tracks is still the cheap guard
# against the silent-lost-code case, so keep pyproject.toml out of this set.
# See CLAUDE.md: parallel-workspace version collisions are a known deferred gap.
