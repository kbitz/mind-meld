- **ANSI-escape sanitization on peer-supplied paths** — `console.print(f"...{rel_path}")` at multiple sites (cli.py:917, 962, 1082, 1096; Track 5B will add more in `_print_pull_summary`) renders ANSI escape sequences without escaping when `rel_path` originates from a peer's manifest. A compromised peer could plant escape chars in a synced filename to confuse terminal output. Low likelihood (requires peer compromise), low impact (visual confusion, no code execution). Fix: `from rich.markup import escape` and wrap each `rel_path` print site. ~1 LOC per call site, ~6 sites. (XS) [plan-ceo-review]

- **`walk_generic_source` double-hashes files when `include_files` entries are nested inside `include_dirs`** — surfaced by Track 5D `/ship` Claude adversarial review. `walk_generic_source` (manifest.py:310) collects paths from include_dirs (rglob) AND include_files (depth-0) into one `collected_paths` list, then hashes each. If a user customizes their config so an `include_files` entry like `"projects/notes.md"` lives inside an `include_dirs` entry like `"projects"`, the file gets hashed twice. The final manifest dict is keyed by relative path so the second write is benign (last-write-wins on identical bytes), but the wasted CPU/IO grows with file size and overlap count. Fix: dedup `collected_paths` via `seen: set[Path]` before the hashing loop, mirroring the `_find_conflict_files` Track 5D pattern. ~5 lines + 1 test. Default config doesn't trigger this (gstack include_files are all bare top-level). (XS) [ship adversarial 2026-04-25]

- **`_find_conflict_files` dedup misses on case-insensitive filesystems (APFS default)** — surfaced by Track 5D `/ship` Claude adversarial review. The dedup uses `(src_name, conflict_path)` as a `set` key; `Path("Notes.md")` and `Path("notes.md")` are distinct keys but APFS resolves them to the same inode. If a user customizes config with `include_files: ["projects/Notes.md"]` and disk has `notes.md`, the rglob and sibling-glob may produce different-cased paths for the same inode. Fix: normalize via `os.path.normcase(str(conflict_path))` on macOS for the dedup key (preserve original `conflict_path` in the emitted hit). Very low likelihood — requires user config with mismatched case AND nested include_files. ~3 lines. (XS) [ship adversarial 2026-04-25]

- **`register_device` rewrites `registered:` timestamp on every self-heal call** — surfaced by Track 5D `/ship` Claude adversarial review. `register_device` writes `"registered": datetime.now(timezone.utc).isoformat()` unconditionally (devices.py:30). For the rare iCloud `.icloud` placeholder TOCTOU case (where `backend.exists()` returns False because only the placeholder is local but the original exists in iCloud cloud storage), the self-heal overwrites with a new timestamp, losing the original first-registration time. The `registered` field semantically means "first registration"; this regresses to "last registration." Fix: change `register_device` to fetch-then-write — preserve existing `registered:` if the entry already has one. ~5 lines + 1 test. (XS) [ship adversarial 2026-04-25]
